# 通信

> "沟通最大的问题在于，人们想当然地认为已经沟通了。"  ——乔治·萧伯纳

通信涉及两个主要方面：通信协议和通信方式

- 通信协议是一组规则集合，用于定义如何在发送端和接收端之间交换数据
- 通信方式则是数据实际传输所用的技术或通道

两者并非完全解耦，一种通信协议往往对应着特定的通信方式，通信方式的具体实现有时就是通信协议

通信协议是一组规则集合，用于定义如何在发送端和接收端之间交换数据

协议涵盖的内容包括：

- 数据格式：比如消息头、数据字段怎么组织
- 传输方式：例如是同步传输还是异步传输
  - 同步传输：发送方和接收方在同一时间点进行通信，确保数据实时传输。常见的同步传输协议有HTTP、WebSocket等
  - 异步传输：发送方和接收方可以在不同时间点进行通信，数据可以在发送后存储在队列中，接收方可以在稍后时间点读取
- 错误检测与纠正：如何确保数据完整性、数据是否失真或者被篡改，以及丢包后的重传机制

## 数据格式

### 端序

Prerequisites: [[计算机基础#端序]]

在通信协议（尤指数据链路层协议）中应当指定传输数据的大/小端端序，并在通信两端做大/小端的编解码

以小端解码为例：

在传输时 int16 的两个字节被拆开按小端传输，接收方需要将两个字节按从左到右从高到低的顺序组装

```cpp
int16_t decode_int16_le(const uint8_t* in) {        // in 0xDE 0xF9 (实际上是 0xF9DE)
    return static_cast<int16_t>(
        static_cast<uint16_t>(in[0]) |              // 低字节 0xDE
        (static_cast<uint16_t>(in[1]) << 8));       // 高字节 0xF9 左移 8 位
}
```

`static_cast<uint16_t>` 告诉编译器 `0xF9DE` 这个位模式请按有符号补码解读（这是因为传输的 int16 是有符号数，和 uint16 这种无符号数的移位运算补位规则不同）

## 校验方法

通信协议的一个重要部分就是错误的检测与纠正，其中验证数据是否失真或者被篡改称为**校验**

常见的校验方法：

### 奇偶校验

**原理**：在数据位后附加一个校验位，使整个数据中"1"的个数为奇数（奇校验）或偶数（偶校验） 
**特点**：硬件实现极简单，但只能检测奇数个 bit 错误，检错能力弱
**典型应用**：串口（UART）通信中可选配置

### 校验和

**原理**：将数据按字节求和，取低位或反码作为校验值，接收端重新计算并比对
**特点**：计算速度快，但对突发错误和字节顺序不敏感，容易漏检
**典型应用**：IP 首部、ICMP、UDP 的简易校验

### 循环冗余校验（CRC）

**原理**：将数据看作一个大的二进制数，除以一个生成多项式，余数即为 CRC 校验码  
**特点**：数学上能检测所有单 bit 错误、双 bit 错误、奇数个 bit 错误及大量突发错误，检错能力极强，但计算量稍大（现代硬件普遍支持）
**典型应用**：以太网帧、CAN 总线、Modbus 协议、存储介质（硬盘、闪存）

### 哈希校验

Prerequisites: [[数据结构与算法#哈希]]

**原理**：通过散列算法（如 MD5、SHA-256）将任意长度数据映射为固定长度的摘要，理论上不同数据产生相同摘要的概率极低 
**特点**：不仅用于检错，还能防篡改（雪崩效应保证微小数据变化导致摘要巨变），但计算成本高
**典型应用**：文件完整性校验、数字签名、HTTPS 证书、Git commit 标识

## 进程间通信协议

基于共享内存的 IPC 通信协议通过共享内存区域在同一计算机系统内的不同进程之间进行通信。在Linux命令行中，可以使用`ipcs`和`ipcrm`命令来管理共享内存段

```bash
#通过ipcs命令查看当前系统中的共享内存段
ipcs -m
#使用ipcrm命令删除不再需要的共享内存段
ipcrm -m <shmid>
```

## 硬件通信协议

References: [10分钟简单解释每个硬件协议](https://www.bilibili.com/video/BV1Swgf6GEaJ)

常见的硬件通信协议有 UART, I2C, SPI, CAN 等，它们一般用于芯片间近距离通信，通过引脚电平变化来传输数据，速率较低

有以下特征分类：

- 串并行：
	- 串行通信：数据在一个信道上逐位依次传输，一次只发送一个 bit
	- 并行通信：数据通过多根信号线同时传输，一次发送多个 bit（通常以字节为单位）
- 双工：
	- 全双工：通信双方能够同时进行双向通信
	- 半双工：通信双方不能同时进行双向通信，只能单向通信
    - 单工：数据传输是单向的，只能由一方发送数据，另一方接收数据
- 时钟（指示接收方采集数据的时间）：
	- 同步：接收方在时钟线传输的时钟信号的指引下采集数据
	- 异步：约定一个采样频率，接收方按照这个频率采集数据
- 电平：
	- 单端：引脚的高低电平都是对GND的电压差，实现简单，但抗干扰能力弱
	- 差分：靠于两个差分引脚之间的电压差来进行通信，抗共模干扰能力强，通信距离可达几公里
- 设备：
    - 点对点：一对一的通信
	- 多设备：一对多的通信

| -------- | ------------------------------------------- | :-- | --- | --- | --- | --- |

| RS-232   | DB9 接口                                      | 串行  | 全双工 | 异步  | 单端  | 点对点 |

## 网络传输层协议

按照[OSI模型](https://zh.wikipedia.org/wiki/OSI%E6%A8%A1%E5%9E%8B)的设计，传输层（Transport Layer）把传输表头（TH）加至资料以形成分组。传输表头包含了所使用的协议等发送信息。

[传输控制协议](https://zh.wikipedia.org/wiki/%E5%82%B3%E8%BC%B8%E6%8E%A7%E5%88%B6%E5%8D%94%E5%AE%9A "传输控制协议")（TCP）及[用户数据报协议](https://zh.wikipedia.org/wiki/%E7%94%A8%E6%88%B7%E6%95%B0%E6%8D%AE%E6%8A%A5%E5%8D%8F%E8%AE%AE "用户数据报协议")（UDP）是最常用的协议

通过计算机网络进行信息交换。其中，TCP（传输控制协议）提供可靠的、面向连接的通信，而UDP（用户数据报协议）则是无连接的通信方式
在Linux命令行中，可以使用诸如ping和nc命令来演示网络通信

```bash
# 使用ping命令进行基于UDP的网络通信
ping 192.168.0.1 #该命令将向IP地址为192.168.0.1的主机发送ICMP Echo请求，并等待接收相应的回复
# 使用nc命令进行基于TCP的网络通信
nc -l 1234  #该命令将在本地监听端口1234，并等待与之建立TCP连接的客户端
# 通过在另一个终端窗口中执行以下命令，可以建立与本地1234端口的TCP连接并在连接上发送消息
echo "Hello, TCP!" | nc 127.0.0.1 1234
```
