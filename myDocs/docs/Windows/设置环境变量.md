# 设置环境变量

## Add

| 方法                                                      | 作用域                      | 持久化 | 当前进程生效 |
| ------------------------------------------------------- | ------------------------ | --- | ------ |
| **`setx`**(CMD/PowerShell)                              | 用户 / 系统                  | ✅   | ❌ 仅新进程 |
| **`set`**(CMD)                                          | 仅当前会话                    | ❌   | ✅      |
| **`[Environment]::SetEnvironmentVariable`**(PowerShell) | User / Machine / Process | ✅   | 可指定    |
| GUI 编辑系统环境变量                                            | 用户 / 系统                  | ✅   | ❌ 仅新进程 |

不要使用 setx，`setx` 是命令行工具,它的工作方式是：**把整个变量值当作纯字符串写入注册表**。这带来两个问题：

- `setx` 内部有 1024 字节限制，PATH 一旦超过，后面的内容会被静默切断，不报错
- 复制"合并 PATH"导致重复：
	在 PowerShell 里执行 `setx PATH "$env:PATH;新路径"` 是最常见的错误写法,因为 `$env:PATH` = 系统 PATH + 用户 PATH 合并值，`setx` 会把这一整坨 (含全部系统路径) 写进用户 PATH。每执行一次，用户 PATH 就多一份系统 PATH 副本

推荐做法是

GUI：`设置 → 系统 → 关于 → 高级系统设置 → 环境变量`，每条 PATH 单独一行编辑

在脚本里安全地追加 PATH 则用 `[Environment]::SetEnvironmentVariable`：

```powershell
# 直接添加不查重
[Environment]::SetEnvironmentVariable('Path', [Environment]::GetEnvironmentVariable('Path','User').TrimEnd(';') + ';C:\MyApp\bin', 'User')

# 用户级(无需管理员),查重后再追加
$p = [Environment]::GetEnvironmentVariable('Path','User')
if ($p -notlike '*C:\MyApp\bin*') {
    [Environment]::SetEnvironmentVariable('Path', $p.TrimEnd(';') + ';C:\MyApp\bin', 'User')
}

# 系统级(需要管理员终端),把 'User' 换成 'Machine'
```

它的优势是不会截断、可精确指定 User/Machine/Process 作用域

只改当前进程则直接赋值或 `$env:`：

```powershell
$env:MYVAR = 'hello'          # 只对当前会话有效
[Environment]::SetEnvironmentVariable('MYVAR','hello','Process')
```

**注意项：**

- 将一些软件添加到用户 PATH 时注意要添加软件所在的目录，但是不用指定到 exe

## Enable

新开的终端会自动读到新的环境变量，但已经开着的程序不会，需要重启程序
