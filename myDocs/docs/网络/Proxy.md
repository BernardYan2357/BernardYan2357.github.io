# Proxy

## [v2rayN](https://github.com/2dust/v2rayN)

相较于广为熟知的代理软件 Clash，v2rayN 提供更多可自定义选项，方便配置路由规则等

v2rayN 新版不适用于 Ubuntu22.04，很多依赖库版本过低，导致 v2rayN 无法安装，更推荐 [Clash Verge Rev](https://github.com/clash-verge-rev/clash-verge-rev/releases/tag/v2.5.8) 或[mihomo](https://github.com/MetaCubeX/mihomo)（命令行客户端，可用 systemctl 管理）

### 导入配置

点击`订阅分组->订阅分组设置`，添加订阅组，在可选地址处填入订阅地址，返回主界面，点击`订阅分组->更新全部订阅`，即可导入配置

### 代理设置

在`Internet选项`->`连接`->`局域网设置`可以查看系统代理的设置：
![[局域网设置.png|514]]

v2rayN 界面下方有系统代理菜单，菜单中的选项是通过修改注册表实现的，注册表的变化也会在上面的设置界面显示出来
 1. **“自动配置系统代理”** ：将注册表 `ProxyEnable` 键值设为 `1`，并把代理地址和端口（`http://127.0.0.1:10808`）写入注册表
 2. “清除系统代理”：将注册表 `ProxyEnable` 键值设为 `0`，并清空地址和端口字段
 3. “不改变系统代理” ：v2rayN 不做任何改变，维持原样
 4. “PAC 模式” ：v2rayN 会在本地开启一个 HTTP 服务（通常是 `http://127.0.0.1:10808/proxy.pac`），然后将该 URL 写入注册表的 `AutoConfigURL` 键值，对应设置中的 “使用自动配置脚本”

#### 应用自身的代理设置

有时候在系统中设置代理选项并不能让部分应用走代理通道，你还需要给应用自身设置代理

以 Codex 为例，你需要创建： `~/.codex/.env`，写入：

```bash
HTTP_PROXY=http://127.0.0.1:10808
HTTPS_PROXY=http://127.0.0.1:10808
ALL_PROXY=http://127.0.0.1:10808
NO_PROXY=127.0.0.1,localhost,::1
no_proxy=127.0.0.1,localhost,::1
```

才能够确保应用走正确的代理端口

### 路由设置

v2rayN 路由功能将入站数据按需求由不同的出站连接发出，以达到按需代理目的，软件默认有以下三种路由规则集可以选择：

- 绕过大陆 (Whitelist) 模式：除国内网站外全部通过节点服务器代理上网
- 黑名单 (Blacklist) 模式：仅黑名单内的网站通过节点服务器代理上网
- 全局 (Global) 模式：所有网站通过节点服务器代理上网

多数是访问国内网站，少数网站需要代理就用黑名单规则。如多数是访问外网，少数访问国内网站就用绕开大陆规则，再根据自己的需要添加过滤的网站

在部分情况下，会发现国内/国外网站无法访问，查看日志，发现需要直连的网站走了代理，就需要在路由设置里面添加一条direct规则；如发现需要代理的网站走了直连，就在路由设置里面添加一条proxy规则

点击`设置->路由设置`，在规则集列表中打开要修改的规则集，新建规则

- 设置别名
- 设置outboundTag: `direct`/`proxy`
- 设置Domain: domain:example.com (如要填写多个域名，使用逗号分隔)

右键规则，选择置顶规则，避免被已有规则覆盖，保存后重新加载网页便可访问

### UWP回环豁免

**UWP** 是微软基于 Windows Runtime (WinRT) API 构建的应用程序模型。常见的UWP应用有Microsoft Store等

UWP核心运行环境为 AppContainer（相当于一个沙盒），不同于传统 Win32 应用有着极大的权限，UWP 存在严格的访问边界。其默认禁止出站连接到 IPv4 回环地址（127.0.0.0/8 网段），也就忽略了Internet选项中的代理设置，直接去连接服务器地址

然而，如果系统代理存在，UWP 会尝试通过系统代理连接。但是由于 UWP 不被允许接收环回流量，连接就被阻断了

解决方法：

- v2rayN `设置`->`解除Win10 UWP 应用回环代理设置`
- 在 AppContainer Loopback Exemption Utility 页面中勾选Microsoft Store等软件，豁免其对回环地址的访问

### TUN 模式

Tun 模式通过在操作系统中创建一个虚拟网络接口（即虚拟网卡），实现对所有出站网络流量的捕获和重定向。这是通过修改系统的路由表完成的，将所有或特定目标的IP 流量都重定向到虚拟网卡。接着，代理程序从这张虚拟网卡读取流量，处理后再发送到原本的目标地址或其他指定的代理服务器。

**TUN 模式在操作系统层面拦截网络流量，不依赖于应用程序的代理支持**，因此可以处理从TCP到UDP的所有类型的流量，可以应用于一些走专用IP通道的应用程序，劫持它们的流量强制走代理

在 v2rayN 中，主界面下方选择“启用 Tun”后，界面会关闭再弹出，同时报错“运行 Core 失败”，看报错信息也看不懂。所幸看到了一篇帖子：[v2rayn tun模式用不了 - 开发调优 - LINUX DO](https://linux.do/t/topic/889155)，认为应将“core从sing_box改为xray”。在软件中翻找相似设置，发现进入“设置->参数设置->Tun模式设置”，关闭“旧版 Tun 保护”（选项描述：启用则使用sing-box TUN,否则使用xray TUN），再次开启 Tun 模式则一切正常
