# 编译

## 编译器

References：
- [How the C++ Compiler Works](https://www.bilibili.com/video/BV1qh411p7Sa)
- [How the C++ Linker Works](https://www.bilibili.com/video/BV1qh411p7Sa)

编译的步骤：

1. 预处理：处理以`#`开头的预处理指令(Preprocessor statement)，如`#include`、`#define`等，把头文件的内容直接复制粘贴到你的代码里，生成`.i`文件
2. 编译：将`.i`文件转换为汇编代码，再转成目标文件`.obj`，这一步只检查语法错误
3. 汇编：将汇编代码转换为机器码
4. 链接：将所有`.obj`文件链接起来，生成可执行文件`.exe`，常见报错：Undefined reference（未定义引用）通常就是链接错误，意思是：“我找到了函数的声明，但找不到它的实现”

上述的步骤需要由编译器来完成，常见的C++编译器有：

- gcc：跨平台的开源编译器，gcc 在 windows 上的发行版为 MinGW
- Clang：由LLVM项目开发的编译器，跨平台
- MSVC（Microsoft Visual C++）：与 Visual Studio 集成，主要用于 Windows 平台

> 工具链是什么：编译器、链接器、调试器等工具的集合，构成了从源代码到可执行文件的完整流程。gcc、Clang、MSVC 本身是编译器，但它们通常包含了完整的工具链

## 构建工具

单文件项目直接用编译器就行，但真实项目有几十上百个文件、库、不同配置（Debug/Release），就需要构建工具自动化管理

- Make：Unix/Linux 系统上的经典构建工具，使用 Makefile 定义构建规则，简单灵活，但 Makefile 语法复杂、易出错
- CMake：跨平台的构建系统生成器，是一个配置工具（不直接编译），而是读取 CMakeLists.txt，然后生成适合当前平台的构建文件（如 Makefile、Ninja 文件、Visual Studio Solution等），简化了跨平台构建的复杂性
- Ninja：一个专注于速度的构建系统（并行构建），通常与 CMake 配合使用，CMake 生成 Ninja 构建文件后由 Ninja 执行构建

## CMake

### 安装

[安装CMake](https://cmake.org/download/)，安装后将 CMake 的 bin 目录添加到用户环境变量 PATH 中，命令行`cmake --version`测试

### 基础操作

一个基本的 CMakeLists.txt 内容：

```cmake
cmake_minimum_required(VERSION 3.10) # 指定 CMake 最低版本
project(LearnCMake) # 定义项目名称
add_executable(LearnCMake
    main.cpp
    calculator.cpp
) # 定义可执行文件由 main.cpp 和 calculator.cpp 构建
```

下面需要根据 CMakeLists.txt 生成目标平台下的原生工程，称为 configure（配置）

`ctrl + shift + p` 打开命令面板，输入 `>CMake: Configure`，选择生成器（GCC或Clang或MSVC），生成完成后，输入 `>CMake: Build`或使用快捷键`F7`，CMake 会调用生成器（如 Make或Ninja）来构建项目，在 build 目录下生成可执行文件

Configure 和 Build 是两个独立的步骤，Configure 生成构建系统，Build 执行构建过程，在未改动 CMakeLists.txt 的情况下，之后只需要执行 Build 即可重新构建项目

使用命令行进行 configure 和 build：

```bash
cmake -B build -S . # 生成构建文件，-B 指定构建目录，-S 指定源代码目录
cmake --build build # 构建项目，-B 指定构建目录
```

### find_package

- [CMake 中配置 find_package 的搜索路径](https://www.cnblogs.com/lovebay/p/18807406)

`find_package()` 是 CMake 中用于查找和配置外部库的命令，使用 `find_package()` 命令时 CMake 会在一些默认的系统路径中搜索包。如果你安装的依赖不在这些默认路径中（例如，你把它们安装到了一个自定义的目录，或者你正在使用一个包管理器如 vcpkg 或 conda），你就需要用到 CMAKE_PREFIX_PATH 来告诉 CMake 额外的搜索路径

添加方法：

- 在终端中设置环境变量 CMAKE_PREFIX_PATH，指向包含库的目录：

```bash
export CMAKE_PREFIX_PATH="path/to/your/library;$CMAKE_PREFIX_PATH" # Linux/MacOS
$env:CMAKE_PREFIX_PATH="path/to/your/library;$env:CMAKE_PREFIX_PATH" # Windows PowerShell
```

- 在 CMakeLists.txt 中设置 CMAKE_PREFIX_PATH 变量，指向包含库的目录：

```cmake
set(CMAKE_PREFIX_PATH "path/to/your/library")
```
