# 计算机基础

## 二进制运算

### 移位运算

左移 `<<`：右边空位补 0，左边溢出丢弃

```cpp
uint8_t a = 0b0000'0101;   // +5
a << 1 = 0b0000'1010;      // 10，相当于 ×2
```

右移 `>>`：

|          | 左边空位补                 | 1111 1011>> 1 的结果   |
| -------- | --------------------- | ------------------- |
| **逻辑右移** | 一律补 0                 | 0b0111 1101 = 125 ✗ |
| **算术右移** | 补**符号位**（正数补 0，负数补 1） | 0b1111 1101 = -3 ✓  |

C++ 里的规则是：无符号数右移 = 逻辑右移（补0），有符号数（补码）右移 = 算术右移（补符号位）

## 数制转换

### 其他进制 → 十进制

规则：**基数 × 位权，各位相加**
示例：$(1101.1)_2 = 1×2^3+1×2^2+0×2^1+1×2^0+1×2^{-1} = (13.5)_{10}$

### 十进制 → 其他进制

- **整数部分**：不断除以基数，记录余数，直到商为0；余数**倒序排列**
- **小数部分**：不断乘以基数，记录整数部分，直到小数部分为0；整数**正序排列**

示例：$(13.2)_{10}$
1. 整数 $13 \xrightarrow{\div2} 1101$
2. 小数 $0.25 \xrightarrow{\times2} 01$
结果：$(1101.01)_2$

### 二进制、八进制、十六进制

二进制在C++中用前缀"0b"表示，十六进制在C++中用前缀“0x表示”，以示区分

关系：$8=2^3,\quad 16=2^4$

#### 二进制 ↔ 八进制

- 二转八：整数左侧补0、小数右侧补0，每3位二进制对应1位八进制（因为3位二进制数才能表示八进制中的最大值7），从小数点划分
  例：$(1101.01)_2 \rightarrow 001\ 101.010 \rightarrow (15.2)_8$
- 八转二：每位八进制拆成3位二进制，最后去掉多余前导0
  例：$(15.2)_8 \rightarrow 001\ 101.010 \rightarrow 1101.01$

#### 二进制 ↔ 十六进制

规则同上，区别：每4位二进制对应1位十六进制

#### 八进制 ↔ 十六进制

中转二进制：$\boldsymbol{8 \rightarrow 2 \rightarrow 16}$

## 数据在计算机中的表示

### 比特与字节

- **比特（bit）**：信息的最小单位，只能表示 0 或 1
- **字节（Byte）**：通常 8 个比特，是内存寻址和访问的最小单位
- **常用单位**：1 KB = 1024 Byte =  $2^{10}$ Byte，1 MB = 1024 KB =  $2^{20}$ B，1 GB = 1024 MB = $2^{30}$ B

### 基本数据类型

各种数据类型本质上由若干字节按照固定规则拼接而成

| 类型        | 常见字节数                | 说明                                         |
| --------- | -------------------- | ------------------------------------------ |
| `uint8`   | 1                    | 无符号 8 位整数，范围 $[0, 255]$ （$2^8 = 256$）      |
| `int8`    | 1                    | 有符号 8 位整数，范围 $[-128, 127]$，用[[计算机基础#补码]]表示 |
| `uint16`  | 2                    | 无符号 16 位整数，范围 $[0, 65535]$                 |
| `int16`   | 2                    | 有符号 16 位整数，范围 $[-32768, 32767]$            |
| `float32` | 4                    | 单精度浮点数：1 位符号 + 8 位指数 + 23 位尾数              |
| `float64` | 8                    | 双精度浮点数：1 位符号 + 11 位指数 + 52 位尾数             |
| `char`    | 1（ASCII）或 1~4（UTF-8） | 字符编码，本质仍是数字                                |

在 STM32/Linux 中，类型名往往会带 `_t`，如 `uint8_t`。这里的"t"是 type 或 typedef（类型定义）的缩写

#### 端序

References: [[嵌入式er笔记]大端小端详解](https://zhuanlan.zhihu.com/p/144718837)

端序（字节序）是指多字节数据的字节在内存中的存储顺序

对于一个32位的数值，我们可以使用16进制来表示：0x1A2B3C4D，由于一个字节可以表示8位整数，即两位16进制数，那么这个32位数值就由 0x1A, 0x2B, 0x3C, 0x4D 4个字节组成。假设内存的地址都是从低到高分配的，那么这4个字节的顺序存储就有两种存储方式：

- **大端序**(Big-Endian)：高位字节在低地址：0x1A 0x2B 0x3C 0x4D 
- **小端序**(Little-Endian)：低位字节在低地址：0x4D 0x3C 0x2B 0x1A

大端序：

符合”从左到右“阅读习惯；基于其存储特点，符号位在所表示的数据的内存的第一个字节中，便于快速判断数据的正负和大小（CPU做数值运算时从内存中依顺序依次从低位地址到高位地址取数据进行运算，大端就会最先拿到数据的符号位 / 最高位

小端序：

基于其存储特点，内存的低地址处存放低字节，所以在强制转换数据时不需要调整字节的内容（比如，把`uint16_t`（2字节）强制转换成 `uint8_t` （1字节），就可以直接把前一个字节给 `uint8_t` 就行；另外CPU做数值运算时从内存中依顺序依次从低位地址到高位地址取数据进行运算，开始只管取值，最后刷新最高位地址的符号位就行，这样的运算方式会更高效一些）

##### 不同架构的端序

| 架构                      | 字节序         | 默认/常见模式 | 代表厂商      | 说明                              |
| ----------------------- | ----------- | ------- | --------- | ------------------------------- |
| x86 / x86-64            | 小端          | 仅支持小端   | Intel、AMD | 桌面、服务器、笔记本的主流架构                 |
| ARM（Cortex-M/A 等）       | **双端**（可切换） | 默认小端    | ARM       | STM32（Cortex-M）默认小端，部分架构支持配置为大端 |
| IBM z/Architecture（大型机） | 大端          | 仅大端     | IBM       | 企业级大型机（zSeries / System z）      |

- **网络字节序**：TCP/IP 协议族规定多字节数据一律使用**大端**（Big-Endian）传输，与 x86 的小端相反，所以网络编程里需要做字节序转换（`htonl` / `ntohl` 等）
- **"双端"（Bi-endian）**：指硬件设计上可以通过配置选择大端或小端，但实际系统只会用一种模式运行。ARM 虽然支持双端，但绝大多数产品和工具链都按小端使用
- 在通信中应当指定大/小端，并在通信两端做大/小端的编解码，对于通信端序与架构端序不匹配的情况，做端序的转换。详情参考：[[通信#端序]]

#### 补码

##### 为什么需要补码？

计算机只能存储 0 和 1，那**负数怎么表示**？有三种方案：

| 名称  | 方案               | 表示 `+5`    | 表示 `-5`    | 问题                                                  |
| --- | ---------------- | ---------- | ---------- | --------------------------------------------------- |
| 原码  | 将最高位设置为符号位，为1则为负 | `00000101` | `10000101` | 存在 `+0`（`00000000`）和 `-0`（`10000000`），且做减法需要复杂的借位逻辑 |
| 反码  | 将正数的各位取反         | `00000101` | `11111010` | 仍然存在 `±0` 问题；减法逻辑依然复杂                               |
| 补码  | [[计算机基础#补码的定义]]  | `00000101` | `11111011` | 只有一个 0；减法可以统一成加法，硬件电路最简单                            |

##### 补码的定义

以 8 位（`int8_t`）为例，要表示正负数，将 0~255 对半拆开：

- **正数**：分配 0~127 空间（0000 0000 ~ 0111 1111），最高位（符号位）恒为 0，规定正数时补码 = 原码
- **负数**：分配 128~255 空间（1000 0000 ~ 1111 1111），最高位（符号位）恒为1，规定负数时补码 = 原码取反（符号位不变）+ 1

为什么补码这样定义？可以用**模运算（取模）** 来解释。以 -5 为例：
$$
-5 \equiv 251 \pmod{256}
$$
我们要表示 -128~-1这些负数，通过模运算将其转换为正数，恰好将 -128~-1 对应到 128~255 这一区间。推广到一般情况：
$$-x \equiv 2^n - x \pmod{2^n}$$
设 x 是 n 位二进制正数，全部位取反记作 $\bar{x}$。由于全 1 的数 = $2^n - 1$：
$$\bar{x} = (2^n - 1) - x$$
两边加 1：
$$\bar{x} + 1 = 2^n - x$$
而 $2^n - x$ 正是 $-x$ 在模 $2^n$ 下的等价表示，所以：
$$-x = \bar{x} + 1$$
即补码 = 原码取反（符号位不变）+ 1，在程序上，数值溢出对应取模操作

使用补码可以统一加减法：
$$x - y = x + \bar{y} + 1$$
其中$\bar{y} + 1$ 即为 $y$ 的补码

##### 补码的数值范围

8 位补码能表示的范围是 $[-128, 127]$：

| 二进制        | 无符号解读 | 补码解读              |
| ---------- | ----- | ----------------- |
| `00000000` | 0     | **0**（唯一的 0）      |
| `01111111` | 127   | **127**（最大正数）     |
| `10000000` | 128   | **-128**（最小负数，特殊） |
| `11111111` | 255   | **-1**            |

注意 `10000000` 是补码的一个特例：取反加一回推其原码会是 `10000000`（自身），它表示 `-128`，不存在对应的正数。类似地，n 位补码范围是 $[-2^{n-1}, 2^{n-1}-1]$：

- `int8_t`：$[-128, 127]$
- `int16_t`：$[-32768, 32767]$
- `int32_t`：$[-2147483648, 2147483647]$

##### 补码的扩张与截断

从 `int8_t` 变 `int16_t`，符号位扩展：

```cpp
int8_t  -5 = 1111 1011
int16_t -5 = 1111 1111 1111 1011
```

因为最高位是 1 表示负数，扩展必须保持符号，所以高位全补 1

从 `int16_t` 变 `int8_t`，直接截断高处字节，结果取决于低字节：

```cpp
int16_t v = 0x1234;     // 4660
int8_t  low = static_cast<int8_t>(v);  // 得到 0x34 = 52
```

#### 浮点数

IEEE二进制浮点数算术标准（IEEE 754）定义了**表示浮点数**的格式（包括负零-0）与反常值（denormal number），无穷（Inf）与非数值（NaN），以及这些数值的“浮点数运算符”；它也指明了四种数值舍入规则和五种例外状况（包括例外发生的时机与处理方式）

## 计算机架构

### x86 架构 

- **起源**：由英特尔（Intel）于1978年推出，最早用于 16 位处理器 8086，后续扩展为 32 位（IA-32）和 64 位，命名源于早期芯片型号以 "86" 结尾（如 8086、80286、80386 等）
- **生产厂商**：主要由 Intel 和 AMD 生产，两家互有交叉授权，共同主导 PC 和服务器市场
- **64 位扩展**： 
	- **x86-64**（又称 **x64**、**AMD64**、**Intel 64**）是 x86 的 64 位扩展，最初由 AMD 于 2003 年推出（AMD64），后 Intel 跟进并命名为 Intel 64。它向后兼容 32 位 x86 代码
	- 现在桌面和服务器系统中运行的 “64 位系统” 几乎都是 x86-64 架构
	- **特点**： 
		- 指令集庞大且复杂（CISC，复杂指令集计算），单条指令功能强，但内部译码复杂
		- 兼容性极强，现代 CPU 仍可直接运行 30 年前编写的软件
		- 制程工艺先进，单核性能高，生态成熟（Windows、Linux 等均有完整支持）
	- **应用领域**：个人计算机、工作站、游戏主机、数据中心服务器、部分嵌入式高性能场景

### ARM 架构 

- 主要用于移动设备、嵌入式系统和部分服务器。以低功耗和高性能为特点，广泛用于智能手机、平板电脑、物联网设备以及苹果 M 系列芯片的 Mac 电脑
- 采用 RISC（精简指令集），指令定长，流水线效率高，能效比出色

### RISC-V架构

- 一种开源指令集架构（ISA），可自由使用和定制，无授权费用
- 具有灵活性和可扩展性，逐渐受到学术界和工业界的关注，用于微控制器、AI 加速器、服务器等场景

## 线程、进程

- 当程序执行时，操作系统将程序加载至内存中，形成可执行程序实例，这个实例被称为进程。一个程序若被多次读取到内存中，就会形成多个进程
- **进程是分配资源的基本单位**，每个进程都有自己虚拟的独立的地址空间、内存、文件描述符等资源。进程内的资源访问可以直接通过虚拟地址进行，但不同进程之间的资源访问需要通过[[通信#进程间通信（IPC）]]机制来实现

一个进程可以包含一个或多个线程，线程是进程中的一个执行单元

> 为什么要有线程？
>
> 假设有一个文本编辑器，它要同时处理用户输入、自动保存文件和检查拼写错误，这三个功能都要访问同一个文档。我们知道，进程是资源分配的基本单位，但如果我们把这三个功能放在同一个进程中，那么它们就会互相干扰。为了避免这种情况，我们可以使用线程来实现并行处理。每个功能都可以在一个独立的线程中运行，这样它们就可以同时访问同一文档

- 线程共享进程的地址空间、文件描述符、堆和全局变量等资源，但每个线程有自己的栈、寄存器和程序计数器
- **线程是CPU调度的基本单位**，线程之间可以并行执行，提高程序的效率和响应能力

线程的状态：

- 一个线程对应一个CPU核心，假如计算机只有一个单核CPU，即一次只能执行一个线程，那就需要对每个线程轮流执行，每次单个计算的时间成为一个CPU时间片（10ms左右）
  - 对于线程来说，等待CPU时处于**就绪**状态，一旦CPU过来执行，就转变成**运行**状态
  - 假如线程在执行时向硬盘发送访问请求，然后等待，这时CPU就变成空转了，线程变成**阻塞**状态，CPU转而执行其他线程，等到硬盘的数据回复，线程从阻塞态转成就绪状态，然后继续执行
- 如果是多个CPU，确实可以让多个线程真正的并行计算，但是往往线程会很多，所以还是需要时间片轮转，为了简化，在内存中为每个线程提供各自虚拟的CPU，每个线程会认为自己是一直独占着CPU，就不需要考虑时间片轮转的问题了

并发 (Concurrency) 与并行 (Parallelism)：

- 并发：多个任务在同一时间段内交替执行，表现出同时进行的效果，但实际上在任何给定的时间点上只有一个任务在执行
- 并行：多个任务在同一时间点上同时执行，通常需要多处理器系统支持
